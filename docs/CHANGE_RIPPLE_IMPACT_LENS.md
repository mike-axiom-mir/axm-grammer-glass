# Change Ripple / Impact Lens

Change Ripple connects a changed item in a caller-supplied 102-Grammar generation comparison to the **recorded structural neighborhood** of its language inside the currently loaded Grammar Glass snapshot.

Flow:

`changed 102 item -> exact language identity -> recorded language atoms -> recorded one-hop relation/carry/memory neighborhood -> recorded Draft/Run constellation references`

## Supported language bindings

The lens only maps item identifier schemes that are explicit today:

- base grammar identity: exact `languageId`
- specialist eye: exact `languageId`
- semantic keyboard key: `languageId:Kxx`
- cheatcode rule: `code.cheat.<languageId>...`

Software-direction, capability-passport and Grammar Bridge items are held as `LANGUAGE_UNMAPPED` unless a future portable snapshot supplies an unambiguous language-scoped identifier. The viewer never guesses.

## Four inspection depths

1. **ORIGIN** — the changed/added/removed imported item.
2. **LANGUAGE** — real recorded atoms carrying that language identity.
3. **NEIGHBORHOOD** — real recorded relation edges, direct carries and contact-memory paths touching those atoms.
4. **CONSTELLATION** — recorded Draft and Run Stars that explicitly carry that language identity.

Dark Grammar relation classes (`CONTRAST`, `REPULSION`, `BOUNDARY`, `UNRESOLVED_NEIGHBOURHOOD`) are surfaced as structural contacts. A new contact is **not** treated as a resolution.

## Truth boundary

Change Ripple is an impact **inspection** lens, not a causal model.

- structural contact is not causal proof
- a changed capability is not automatically an improvement or regression
- language identity alignment is not semantic equivalence
- a Dark Grammar contact is not Dark Grammar resolution
- a Dark Grammar contact is not a physics claim
- the lens creates no evidence, candidate, execution request, history, ranking, winner, re-entry or mutation
- recorded Grammar Glass and imported 102-Grammar snapshots remain separate provenance-bound sources

The lens is bounded for display/receipt size. Counts record the full matched sets while refs may be truncated by explicit limits.
