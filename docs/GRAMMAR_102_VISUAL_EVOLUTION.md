# 102-Grammar visual evolution inside Grammar Glass

This viewer layer makes imported 102-Grammar capability generations visible inside the existing Grammar Glass / Ghost Glass experience without turning the import into a merge, activation, default replacement, score, or authority grant.

## Flow

```text
caller-supplied 102-Grammar capability snapshot A
  -> validated import receipt
  -> explicit viewer lens selection
  -> deterministic visual projection

optional capability snapshot B
  -> second independent import receipt
  -> generation comparison
  -> Ghost membrane A/B projection
```

The viewer never fetches or clones the 102-Grammar repository. Source repository, commit, optional tree, profile snapshot and capability-snapshot digests remain explicit bindings supplied by the caller.

## Seven visual lenses

The viewer can expose the same seven separate intake layers without flattening them into one score:

- base grammar identities
- specialist eyes
- semantic direction keys
- cheatcode influence inventory
- software direction profiles
- G0-G6 capability-passport inventory
- Grammar Bridge Atlas inventory

A layer may remain `PRESENT`, `ABSENT`, or `UNKNOWN`. Missing data is not interpreted as language incapability.

## A/B generation behavior

When both generations are loaded, the visual plan uses the intake comparison receipt directly:

- shared unchanged item identities remain faint on both sides;
- items only in A remain on the A side;
- items only in B remain on the B side;
- equal stable IDs with changed digests receive a visible A-to-B trail across the membrane;
- state, digest, metric and item-count deltas remain inspectable per lens.

Changed items are prioritized into the bounded render set so a change late in a large layer such as the 4,896-key semantic inventory cannot disappear merely because the canvas samples for performance.

## Projection boundary

The visual geometry is intentionally non-semantic.

A mark's position does **not** mean semantic distance, compatibility, quality, importance, confidence, causality, maturity level, bridge topology, cheatcode influence edge, or Dark-Grammar resolution. Shapes only distinguish viewer lens categories. The bridge lens uses diamond marks rather than invented source-to-target lines because the intake receipt does not necessarily carry bridge endpoint topology.

The visual layer creates no evidence, cycle mutation, contact-memory mutation, Draft Star, candidate, execution request, automatic re-entry, ranking, winner, semantic-equivalence inference, imported-capability activation, or default-source replacement.

## Ghost Glass integration

`ghost-glass.js` loads the 102 evolution viewer as an optional local viewer extension. The generation membrane and the existing Ghost Glass membrane stay synchronized when both are present. If no 102 capability snapshot is loaded, ordinary Ghost Glass behavior is unchanged.
